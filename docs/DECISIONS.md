# Decisions log

Choices made where the spec was ambiguous or a human checkpoint could not be reached. Each can be revisited.

| # | Decision | Why |
|---|---|---|
| D-001 | **Built through M0–M9 without stopping at checkpoints A–D.** No credentials were invented. Everything that needs a key works in **local-only mode** and switches on when env vars are set. | The owner asked for a complete, tested build in one pass. The checkpoints' questions are listed in `PROGRESS.md` → *Waiting on you*. |
| D-002 | **Local-first architecture.** All content, progress, mocks, orals, SRS and trackers live in IndexedDB (Dexie). Supabase is an optional sync target behind a `SyncBackend` interface (`apps/web/src/lib/sync.ts`). | Offline-first is mandatory. The app is fully usable with no account and no network. |
| D-003 | **Two oral examiner engines.** (1) *Offline examiner*: an on-device state machine (`packages/learning/src/oral.ts`) that asks questions from the bank, probes weak answers with follow-ups, and grades against each item's key points by keyword-group matching. (2) *AI examiner*: the `oral-examiner` Edge Function (Claude) grades semantically against the same key points. | Officers at sea need oral practice with no signal. The offline grader is calibrated by a test that requires every item's own model answer to score ≥ 80% and an irrelevant answer to score < 35%. |
| D-004 | **Key points carry optional `match` keyword groups** (`"a\|b\|c"` synonyms per group) and `critical: true` for safety-critical questions. | Makes offline grading deterministic and reviewable, and lets the app fail an oral on one unsafe answer, as real examiners do. |
| D-005 | **Oral pass rule (draft):** average ≥ 70% of key points AND no critical question < 50%. | No official rubric is available. Kept strict on safety. |
| D-006 | **Practice mock format when config is null:** 50 questions, 120 minutes, 70% pass, labelled "Official format not yet confirmed". | Per spec M5. |
| D-007 | **Syllabus weights** for mocks and "study next": NAV 1.0, STAB 1.2, CARGO 1.1, COLREG 1.0, LAW 1.1, MGMT 0.9, LOCAL 0.6. "Study next" priority = (1 − score) × weight. Unstarted topics come first. | The spec says "lowest score × syllabus weight". We use the deficit so that weak areas rank highest. Weights are a draft for expert tuning. |
| D-008 | **Exam-readiness bars are deliberately higher than pass marks:** ≥ 90% coverage, every competence ≥ 85% (latest attempt per item), last 20 calcs ≥ 85%, 3 consecutive mocks ≥ 85%, 3 orals averaging ≥ 80% with no critical failure. | So that "passing in the app" means margin on exam day. |
| D-009 | **Learning techniques built in:** SM-2 spaced repetition with confidence-weighted quality (confident errors re-queued in 10 minutes), interleaved mixed quizzes, unseen and missed items served first, worked examples with progressive step reveal and reduced credit for hints, fresh random numbers per calculation, option-order shuffling per attempt, timed mocks with no feedback, a study planner by exam date, voice orals. | See `apps/web/src/features/more/Techniques.tsx`. |
| D-010 | **MCQ answer positions rebalanced** (`scripts/rebalance-mcq.ts`) and **options shuffled at display time.** | The content test found 55% of answers were "B". That pattern can be exploited and wouldn't transfer to the real exam. |
| D-011 | **Sea-time months = days / 30**, with overlapping periods merged. | Authorities differ. Flagged in `CONTENT_TODO.md`. |
| D-012 | **Offline bundles** are gzipped JSON per country, content-hashed and versioned, with installer magic-byte detection. | Some servers/CDNs transparently decode `.gz`, which broke installation in testing. |
| D-013 | **Production content gate:** `pnpm content:gate` (CI job) fails if any non-reviewed item would ship in a prod bundle. RLS also hides drafts from non-admins when `app.content_mode = prod`. | Spec rule 5 / M9. Today the prod bundles are therefore **empty** until reviewers approve items. |
| D-014 | **AI model:** `claude-opus-5-5` via the official Anthropic SDK in Edge Functions, with structured outputs (Zod), effort `medium`, one retry on invalid output. **Scores are recomputed in code** from the points the model marks as hit, and hallucinated points are discarded. | "Numbers come from code" (spec rule 7) and the grounding rule. Change `MODEL`/`PRICE` in `supabase/functions/_shared/` if you choose a cheaper model. |
| D-015 | **Admin review in local mode** exports a decisions JSON. `pnpm content:apply-reviews` writes it into the YAML (status, reviewer, date). With Supabase it also updates `items`. | Keeps content Git-reviewable (spec §2). |
| D-016 | **UI:** Tailwind + Radix (Dialog, Progress, Tabs), neutral navy/teal brand, app name "Chief Mate Prep" (placeholders, Checkpoint A). Teal darkened to pass WCAG AA contrast. | |
| D-017 | **Performance:** routes code-split, supabase-js loaded on demand. Initial load is ~129 KB gzipped against a 170 KB budget enforced by `pnpm size:check`. | M9. |
| D-018 | **No past papers or copyrighted banks reproduced.** Public collections (e.g. paid "MCA orals past papers", Jahajee, Macneil's notes) were reviewed for *topic frequency* only. Every question and answer is original. | Spec rule 6. See `ORAL_QUESTION_BANK.md`. |
| D-019 | **RLS tests run on plain Postgres 16** with a minimal `auth` stub (`supabase/tests/auth-stub.sql`, `pnpm test:rls`). | The Docker daemon / Supabase CLI isn't available in the build sandbox. Re-run with `supabase start` once the project exists. |
